# Set up Thursday on the Workstations (week 3, day 4)

For the trainer. Thursday's three exercises run in each learner's Google Workstation terminal, with the Databricks CLI and Codex, against the class's Databricks workspace. Thursday makes no table: it reads Monday's `course.returns` tables and the eight tables Wednesday's notebook wrote in each learner's schema `course.learner_NN`. Do these steps before class, in order.

## Before Thursday

1. **Get the files.** On your own Workstation, in a terminal in the course folder, run `git pull`. The folder `week-03/day-04` and the files `week-03/setup/day-04-*` are there. On a learner's Workstation, `git pull` can stop with `Your local changes to the following files would be overwritten by merge`, naming week 2's notebooks: the Workstation saves a notebook as soon as it runs, and the course has changed those notebooks since (checked on 2026-11-16). Exercise 1's start tells the learner to run `git stash`, then `git pull` again.
2. **Each learner installs the Databricks CLI, before class.** The Workstation configuration has no `databricks`, and a Workstation keeps only its home folder across a stop. So each learner installs the CLI in their own home folder with the day's README, "Before Thursday", step 1 (`~/.local/bin`, version 1.25.0). Post that part of the README with the day's message. On one learner's Workstation, `databricks -v` must print a version of 0.205.0 or above ("This version should be 0.205.0 or above", Databricks' CLI tutorial).
3. **The workspace address.** Write the workspace URL on the board, or in the day's post, as `https://` and the host. Learners type it before class and again only if exercise 1, step 3, shows `NO`.
4. **Each learner saves the profile `course`, before class.** The README's "Before Thursday", step 2: `databricks auth login --host <workspace-url> --profile course`. The Workstation asks whether to open an external website: the learner selects **Copy**, not **Open**, and pastes the address into a new browser tab. **Open** changes the address, and the sign-in fails with `state mismatch` (checked on 2026-11-16). After the sign-in, the browser goes to `http://localhost:8020/...` and cannot reach it, because the CLI waits on the Workstation; the learner copies that address and runs `curl "<address>"` in a second Workstation terminal, and the CLI prints `Profile course was successfully saved`. Then `databricks auth profiles` shows `course` with `YES` under Valid. Check it on two or three learners' Workstations the day before.
5. **When a sign-in cannot complete.** There is no token fallback: learners may not use personal access tokens in this workspace ("User does not have permission to use tokens", checked on 2026-11-13 as a learner). Such a learner does exercises 1 and 2 in the workspace's web terminal instead: open any notebook of their Git folder of the course, attach Serverless, and select the terminal icon at the bottom of the right bar. The CLI there is already signed in as the learner. They type the same commands without `-p course`; in exercise 1, step 3, they run `databricks current-user me` in place of `databricks auth profiles`, and write `course`, `YES` and its exit status when it prints their user name. Exercise 3 then judges the fallback transcript (its step 3).
6. **The right to run jobs, and job compute.** Exercise 2 runs `databricks jobs submit` with `week-03/day-04/exercise-02-run-wednesday-as-a-job/job.json`. The file names no compute, so the run takes the workspace's default ("serverless compute is the default for all tasks that support it"). Check that serverless compute for jobs is on for the workspace, and that the learners may run jobs. If it is not on, add a cluster to the file's task before class (`existing_cluster_id`, the class compute's id), commit, and tell the course team.
7. **The path in job.json.** The file names each learner's copy of Wednesday's notebook as `/Workspace/Users/<user name>/irs-bpa-to6-2026-11-02-exercises/week-03/day-03/wednesday-tables`, with no `.ipynb`: a notebook in the workspace is named without it (to confirm, item 4 below). The learner writes the user name; the rest is the course's. Open one learner's Git folder in the workspace. Check that the folder's name is `irs-bpa-to6-2026-11-02-exercises`, and that the notebook's full path (on its menu, copy its full path) matches. The path has no `.ipynb`: a job given the path with `.ipynb` fails ("Notebook has been removed", checked on 2026-11-13). If a part differs, change `job.json` and commit before class.
8. **Codex at its default settings.** On a learner's Workstation, start `codex` in `week-03/day-04/exercise-03-codex-checks-the-sets`, ask it to run `databricks catalogs list -p course`, and check that it asks before it runs the command. If it runs it without asking, the Workstation's Codex settings are not the default: type `/permissions` to see them, and have them reset before class. At the default settings (`/status` shows `Workspace (Ask for approval)`), Codex runs a `databricks` command with `--help` without asking, since help never reaches the workspace, and asks before each other one (checked on 2026-11-16). In class, a learner whose Codex runs another `databricks` command without asking stops it with Ctrl+C and calls you.
9. **Wednesday's tables in each learner's schema.** Run `databricks tables list course learner_NN -p <your profile>` for two or three learners. Each schema should hold `return_table`, `dependents`, `w2s`, `features`, `feature_record`, `train`, `valid` and `test`. A learner whose schema is empty runs exercise 2 first: the job writes the tables.
10. **The fallback transcript.** `week-03/setup/day-04-codex-transcript.md` is the course's run of six proposed commands (one without `-p`, one `jobs delete`). Read it once. Learners use it when their own Codex run proposes no command to judge.

- Demo before exercise 3: ask Codex whether `course.returns.return_header` has the column `exam_changed_tax`. Decline one command, and say which of the four questions decides it.

## After class

Nothing to reset in the workspace. A learner who did the optional part of exercise 3 has a saved job in their name: they may delete it with `databricks jobs delete <job id> -p course`, after the four questions.

## Checked on a Workstation

The course team wrote Thursday on a computer with no Databricks access. On 2026-11-16 the course team ran the three exercises on a learner's Workstation, as a learner, and each reached `Done:`. Each exercise's `decisions.md` says what ran, under "Where it ran". What the run showed, item by item:

1. **Before class: the browser sign-in completes from a Workstation.** Yes, with **Copy** and `curl`, as in step 4. **Open** fails with `state mismatch`. There is no token fallback (step 5). Page: https://docs.databricks.com/aws/en/dev-tools/cli/tutorial ("In your web browser, complete the on-screen instructions to log in").
2. **Exercise 1: what `tables list` and `tables get` print.** `tables list` prints one line per table, with its full name and type. `tables get` prints JSON whose `columns` entries hold `name` and `type_name` (`INT` for `total_income`), and `comment` only for a column that has one: `total_income` has none, `wages_amt` has one. Pages: https://docs.databricks.com/aws/en/dev-tools/cli/reference/tables-commands; https://docs.databricks.com/api/workspace/tables/get.
3. **Exercise 2: the run starts, on job compute, as the learner.** `databricks jobs submit --json @job.json --no-wait -p course` printed the run id at once, with exit status 0. Page: https://docs.databricks.com/aws/en/dev-tools/cli/reference/jobs-commands.
4. **Exercise 2: the notebook path, and what the run writes.** The path without `.ipynb` reached the learner's notebook. After about two minutes, `jobs get-run` showed `status.state` `TERMINATED` and `termination_details.code` `SUCCESS`. `features` held 52 rows before and after, and its last change fell inside the run. Page: https://docs.databricks.com/api/workspace/jobs/getrun.
5. **Exercise 3: Codex asks before each `databricks` command.** Yes, for each command that reaches the workspace. A `databricks` command with `--help` runs without asking (step 8). Page: https://developers.openai.com/codex/agent-approvals-security ("Codex asks for approval to edit files outside the workspace or to run commands that require network access.").
6. **Exercise 3: a run that Codex finishes in time.** Codex proposed four commands, `databricks tables get course.learner_NN.<table> --profile course --output json` for `features`, `train`, `valid` and `test`, and answered in under two minutes. Its prompt offers three choices: `1. Yes, proceed (y)`, `2. Yes, and don't ask again for commands that start with databricks tables get (p)` and `3. No, and tell Codex what to do differently (esc)`. Exercise 3, step 3, names the first and the third, and tells the learner not to take the second.
